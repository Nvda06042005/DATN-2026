# Excel entry calendar

The source files here are the full application macro. `vbaProject.bin` is generated by `scripts/build-entry-vba.py` using build-only `pyOpenVBA==6.6.0` (MIT license included). The backend only attaches these reviewed bytes to a newly generated template; it never runs any macro from an uploaded file. No Python or Office installation is needed on Render.

The workbook defines `DongAPrefix`, `DongAOffset`, `DongAMinYear`, and `DongARequireEmail`. The macro only edits columns A/B of confirmed entry rows and the selected birthday cell in its own workbook. It does not use networking, shell commands, registry access, external workbooks, or filesystem commands. Enter bindings apply while this workbook is active and are restored on deactivate/close. Rebuilding keeps the source available for review.

Use Microsoft Excel desktop on Windows. A small vector calendar icon follows the selected entry row beside its birthday cell. Click the icon or birthday cell to show a small calendar, choose month/year/day, then press Enter to confirm the row and move to the next full-name cell. Form/control dimensions are applied in points at runtime to avoid clipping with Windows display scaling. Enable content for this known downloaded template if Excel asks. A file blocked as downloaded content may need to be unblocked in that file's Properties; do not lower global macro security or add a broad trusted folder.

Native QA used an isolated Microsoft Excel 16 instance, not the WPS COM handler also registered on the development machine. Verified blank numbering, the real UserForm, typed birthday, explicit Enter, code generation, edit invalidation, save, and server re-read of the Excel-saved file. Unit/API tests validate the macro attachment and member-only `.xlsm` upload policy separately.
